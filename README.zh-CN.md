# DeepSeek Harness 移动端适配层

> **本仓库是过渡方案，预期会被归档。**
> 它只服务于官方 DeepSeek Harness Web 前端尚未提供移动端布局的这段时间。官方支持移动端适配后，
> 本仓库归档、安卓应用移除该子模块，下述规则全部删除而非迁移。

面向 Android/WebView 的官方 DeepSeek Harness Web 前端适配层。**官方产物绝不修改**：
构建过程逐字节校验并原样复制官方包，只额外注入一个样式表（`dsh-android.css`）
和 `viewport-fit=cover` 视口声明。

[English](README.md) · [简体中文](README.zh-CN.md)

## 存在的理由

官方前端为桌面三列布局设计。在手机（360–412px）上该布局存在可实测的缺陷。
下表数字均在 360×800 移动视口下实测得出，非估算。

| 缺陷 | 修复前 | 修复后 |
| --- | --- | --- |
| 窄屏展开侧栏时聊天区被挤压 | 16px | 256px |
| 输入卡宽度（侧栏折叠态） | 208px | 240px |
| 输入框字号（低于 16px 时 WebView 聚焦缩放且不还原） | 14px | 16px |
| 图标控件触控目标 | 24–28px | 44px |

## 样式表做了什么

**修复此前静默失效的覆盖规则。** 适配层原本已声明 44px 触控目标与 16px 输入字号，
但用的是**元素**选择器（特异性 0,0,1）。官方产物通过 CSS Modules 哈希**类**选择器
（0,1,0）设置控件样式，永远胜出 —— 因此那些规则在真机上一条都没生效。现已改用 `!important`。

**扩大触控目标而不改动布局。** 官方 UI 把图标控件按 16–28px 的固定 `height` 密集排布。
`min-height: 44px` 会赢过它并撑破密集行，因此改用居中的 `::after` 伪元素扩大热区，
布局盒仍保持官方尺寸。两个官方样式表均未声明任何 `::after`，不存在覆盖冲突。

**把侧栏改为覆盖式抽屉。** 在应用自身的 1024px 断点以下，侧栏会自动折叠为 56px 导轨，
但重新展开会形成 280px 的 **grid 轨道**，把聊天区挤到 16px。抽屉方案让侧栏浮在聊天区之上
而非挤占空间。56px 导轨被刻意保留：它承载着重新展开侧栏的唯一入口。

**回收窄屏侧向留白。** 输入区 clearance 与 680px 桌面内容宽度下限是为桌面阅读舒适度设定的，
在 360px 屏上会消耗 64px 边距。

**移除纯指针交互件。** 聊天宽度与列宽拖拽把手依赖指针精确拖拽，触屏上无法瞄准、只会误触。

安全区内边距、`100dvh` 尺寸、键盘安全的对话框高度、代码块与宽表格的惯性滚动、
以及降低动效偏好同样在覆盖范围内。

## 本层遵守的约束

- **绝不打补丁修改官方产物。** 仅 `index.html` 增加一个标记 meta、`viewport-fit=cover`
  视口声明和一个 `<link>`。
- **不使用 JavaScript。** 纯 CSS 实现，因此没有点击遮罩关闭抽屉的能力 ——
  关闭仍走导轨上的 toggle。
- **`!important` 绝不逸出窄屏保护。** 所有强制声明都位于 `max-width: 720px`、
  `pointer: coarse` 或 `prefers-reduced-motion` 之内。桌面与平板完整保留官方尺寸。
  有测试通过遍历花括号深度来强制这一约束。
- **优雅降级。** 抽屉依赖 `:has()`（Chrome 105+）。不支持时该规则块整体失效、
  侧栏退回轨道形态 —— 即当前行为，不会比现状更差。
- **只使用稳定契约选择器。** frame 元素没有稳定类名（被 CSS Modules 哈希），
  故通过 `[data-shell-overlay]` 与 `[data-rightbar-col]` 结构化命中。
  绝不引用哈希类名。

## 构建

Node.js 24.14.0 与 pnpm 11.19.0：

```text
pnpm install
pnpm test
pnpm build
```

官方前端来自 `@deepseek-ai/dsh-web-frontend@0.1.5-rc.2`。构建会先校验官方
`index.html` 中的每个资源路径 —— 拒绝外部入口与目录穿越 —— 再把包内产物复制到 `dist/`。

`pnpm test` 断言：官方文件逐字节留存、入口未被改动、仅新增一个文件，
以及上述规则存在且作用域正确。

安卓应用以固定版本 Git 子模块方式消费本仓库。生成的 `dist/` 产物与依赖不纳入版本管理。
